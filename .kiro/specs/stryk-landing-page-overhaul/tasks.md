# Implementation Plan: STRYK Landing Page Overhaul

## Overview

Replace the default Next.js starter in `clerk-nextjs` with a locked, full-screen mobile-app-style landing experience backed by Clerk authentication. The work progresses in four phases: (1) environment and dependency setup, (2) shared infrastructure (CSS tokens, layout, middleware, components), (3) landing page, and (4) onboarding flow.

All code is TypeScript/React. `useRouter` must be imported from `next/navigation`. `"use client"` is declared only on files that require client-side hooks. The project uses Tailwind CSS v4 (`@import "tailwindcss"` — no config file), so custom values must use inline styles or CSS custom properties rather than `tailwind.config.js` extensions.

## Notes

- Tasks marked with `*` are optional and can be skipped for a faster MVP
- All code is TypeScript; no `any` types in public interfaces
- Tailwind CSS v4 is in use — do **not** create a `tailwind.config.js`; use CSS custom properties or inline styles for values outside the default Tailwind scale
- `useRouter` must always be imported from `next/navigation` (not `next/router`)
- `CLERK_SECRET_KEY` must never appear in any file with `"use client"` at the top
- The `middleware.ts` file lives at `clerk-nextjs/middleware.ts` (project root), not inside `app/`
- `ImageWithFallback` and `PlayerCard` must both carry `"use client"` since they use `useState` and event handlers
- The `OnboardingPage`'s secondary auth guard (`useUser`) is a belt-and-suspenders measure; the `clerkMiddleware` in `middleware.ts` is the authoritative gate
- `fast-check` and `@testing-library/react` are dev-only dependencies; install with `-D`
